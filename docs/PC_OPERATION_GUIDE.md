# 関東U-15女子 得点ランキング PC運用手順書

## 1. PC中心運用の目的
PCを通常更新・検証・Git管理の中心とし、GitHubを共有・公開の正本とする。運用ルールを最優先とし、自動補完せず、不明点はHOLDとする。mainへ直接pushせず、git add .を使わない。

## 2. 通常更新フロー
1. mainが最新・clean、変更前検証PASSであることを確認する。
2. 更新専用ブランチを作成する。
3. 公式元データで確認できた事実だけを更新する。
4. status=playedだけを列・順序を変えず抽出する。
5. 得点イベント、個人・チームランキング、順位表、次節カード、試合別得点者表示に必要な生成物を更新する。
6. rankings、standings/fixtures、match scorersの3検証とファイル単位の差分確認を行う。
7. PASS後に公開候補を確認し、条件を満たす場合だけindex.htmlへ反映して再検証する。
8. 確認済みファイルだけ個別にstageし、作業ブランチへcommit・pushする。
初回は完全自動化せず、工程ごとに人が確認する。

## 3. HOLD条件
- 元データで選手名、チーム名、得点、日付、試合結果を確認できない。
- goals>0でteamまたはplayerが空欄。
- 試合スコア、イベント、個人、チーム、各区分の合計が不一致。
- 3検証のいずれかが実行不能、終了コード非0、またはVERDICT=PASSでない。
- 意図しない変更、未追跡ファイル、競合がある。
- main上で更新しようとしている、または公開候補を確認できない。
goals=0の診断行はイベントに残してよいがランキングから除外する。2026_D2_m26の0-0診断行は現行ルールに従う。

## 4. index.html公開反映条件
更新後の3検証PASS、全合計一致、公開候補の行数・得点・出典・表示と差分を確認済み、更新専用ブランチ上、の全条件を満たすこと。試合別得点者は直近1試合、チーム別表示、過去試合切替を確認する。検証前に上書きせず、公開反映は原則index.htmlのみ。

## 5. git add対象の考え方
git add .、git add -A、広いワイルドカードは禁止。statusとファイル単位のdiffで確認したファイルだけ個別指定する。バックアップ、ログ、診断、未確認生成物はstageしない。

## 6. 旧スマホ用スクリプトの注意
tools/ranking_update_2026.shは旧Termux用として残し、変更せず、PCでは直接実行しない。旧パスと旧工程を前提とし、現行PC構成と正式検証を完全には反映しない。

## 7. スマホTermuxの方針
外出時の確認・緊急対応用として残す。PCと同時編集せず、開始前にGitHubとの同期を確認する。同じルールを適用し、不明点はHOLDとする。
## 安全確認スクリプトの判定仕様

- mainかつclean: HOLD。mainで直接更新作業を始めないため。
- 作業ブランチかつcleanかつ検証PASS: PASS。
- 変更または未追跡ファイルあり: HOLD。
- 検証失敗、検証スクリプト不在、必須パス不在: FAIL。

このスクリプトは確認専用であり、ファイル変更、stage、commit、push、index.html上書きを行わない。

## Codexへの更新依頼

通常のランキング更新は、Codexへ基本的に「更新して」と依頼する。Codexは作業開始前に docs/CODEX_UPDATE_RULES.md を読み、同ファイルから指定される関連ルールと本手順書を確認してから更新を開始する。
