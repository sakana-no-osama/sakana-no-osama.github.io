# Codex 更新運用ルール

## 適用開始

ユーザーから「更新して」と依頼されたら、作業を始める前に次の3ファイルを読む。

1. docs/CODEX_UPDATE_RULES.md
2. docs/CODEX_RULES_U15_RANKING.md
3. docs/PC_OPERATION_GUIDE.md

3ファイルのルールをすべて適用し、矛盾または解釈できない点があればHOLDとして人間へ確認する。

## 作業開始ルール

- main上で直接作業しない。
- mainがcleanで、変更前検証がPASSであることを確認する。
- 必ずmainから作業ブランチを作成する。
- git add .、git add -A、広いワイルドカードを使用しない。
- 元データにない情報を自動補完しない。
- 不明点、取得不能、データの矛盾、得点不一致があればHOLDとして停止する。

## データ更新ルール

- goal_events CSVに存在しない得点者、得点、チーム名を追加しない。
- 元データで確認できない選手名、チーム名、得点、日付、試合結果を追加しない。
- 0-0試合などのgoals=0診断行はgoal_events CSVに残してよいが、ランキング集計から除外する。
- goals>0の行でteamまたはplayerが空欄ならHOLDとする。
- 試合スコア、goal_events、個人ランキング、チームランキング、DIV1・DIV2の合計を照合する。

## 更新フェーズ

1. 公式の元データを取得・確認する。
2. 確認できた事実だけをデータへ反映する。
3. 得点イベント、個人ランキング、チームランキング、順位表、次節カード、試合別得点者表示に必要な生成物を更新する。
4. ファイル単位で差分を確認する。
5. 次の3検証を実行する。
   - python tests/verify_2026_rankings.py
   - python tests/verify_2026_standings_fixtures.py
   - python tests/verify_2026_match_scorers.py
6. 3検証すべてがPASSでなければHOLDまたはFAILとして停止する。

更新フェーズではindex.htmlを上書きしない。

## 公開フェーズ

公開フェーズは更新フェーズの検証PASS後にのみ開始する。

1. 公開候補HTMLを生成する。
2. 行数、得点、出典、表示、差分を確認する。試合別得点者は、直近1試合、チーム別得点者、過去試合切替も確認する。
3. 問題がない場合だけindex.htmlへ反映する。
4. 反映後に3検証を再度実行し、すべてPASSであることを確認する。
5. 変更対象を個別に確認し、必要なファイルだけを個別指定してstageする。

検証PASS前にindex.htmlへ反映しない。mainへのmergeおよびpushは、人間が差分と検証結果を確認し、明示的に許可した後だけ行う。

## 報告

各作業の最後は、必ず次のいずれかで報告する。

- VERDICT=PASS
- VERDICT=HOLD
- VERDICT=FAIL

HOLDまたはFAILの場合は理由と、実行していない後続工程を明記する。
